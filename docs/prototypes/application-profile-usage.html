Lifecycle at a glance

Source template is reusable. Each Application receives an independent deep clone.

Overview
  1. Selected officer configures and publishes a source Application Profile.
  2. On Application create, the picker lists profiles that match freeform applicability criteria.
  3. Choosing a profile deep-clones structural config onto the Application.
  4. Officers edit only the 14 allowlisted field values; nested Word/Excel fill uses those values + defaults + {{…}} automatic fields.
  5. No write-back to source; source edits never update existing clones.

1. Configure source profile (wizard)

Permissioned officers use the wizard (Excel sections). Legs, states, and template files live on the profile.

Story A
  1. Open Application Profiles → New.
  2. Step through Identity → Results & fields → Process & SLA → Templates & person → Review.
  3. Mark required properties (form + merge) and defaults; embed legs; enable states; upload nested Word/Excel files.
  4. Person checkboxes gate readiness and template roster columns.
  5. Optional freeform criteria for picker filtering.
  6. Publish. Interactive detail: application-profile-wizard.html

2. Create Application — pick profile

Picker shows matching profiles; Accept creates the Application with a deep-cloned profile instance.

Story B
  1. New Application → Choose Application Profile.
  2. List filtered by freeform criteria + audience / action family as needed.
  3. Preview route, produce capabilities, legs, templates.
  4. Use profile (clone) → deep-copy structural config; seed the 14 allowlisted fields from defaults.
  5. Later Word/Excel fill resolves {{…}} from Application values, falling back to profile defaults when empty.

3. Application owns the clone (limited edits)

Structural profile is frozen on the Application. Officers change only the allowlisted field values used by the form and by nested Word/Excel merge.

Story C
  1. Application detail shows profile lineage and the 14 allowlisted fields (Visa Type … Entry Check Point).
  2. Edit those values only — not legs, state checklists, nested files, or which properties are required.
  3. Progress reads the frozen structural clone; Word/Excel fill uses Application values + defaults + automatic placeholders.
Editable: Visa Type, Visa Category, Visa Period, Border Zone, Migration Service, Start/End Date, Region (City), Business Trip Address, Project, Urgency, Work Permit Location, Entry Date, Entry Check Point.
Frozen on Application: directed to (ministry / migration), may be for (employee / FM / visitor), related to (issuance / cancellation / registration / business trip), produce (invitation / WP / visa / border zone / work location), cancel-existing sets, plus legs / states / templates / person flags / required-property config. No re-sync to source.
