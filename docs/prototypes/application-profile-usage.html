1. Configure Application Profile

Wizard sets live configuration and defaults for per-Application fields.

Story A
  1. Open Application Profiles → New / Edit.
  2. Set Related to, route, produce/cancel, legs, states, nested templates, person toggles.
  3. Set defaults for per-Application properties (Visa Type, Period, …).
  4. Publish. Detail: application-profile-wizard.html

2. Create Application — choose profile

Sets live FK and seeds per-Application defaults once.

Story B
  1. New Application → Choose Application Profile (freeform criteria filter).
  2. Use profile → Application.ApplicationProfile FK set.
  3. Copy defaults into empty per-Application fields (Visa Type, signatory, …).

3. Work on Application

Visibility and process rules come live from the profile; officers edit only per-Application values.

Story C
  1. Read-only profile identity (name/code) and template list from live profile.
  2. Edit per-Application fields that are visible (template ∪ workflow).
  3. Progress uses live legs/states/SLA from profile.
  4. Later profile config edits (e.g. Related to, new template) affect this Application’s behavior without wiping entered values.
Full profile clone rejected: configuration must stay centralized. Only per-Application values diverge.
