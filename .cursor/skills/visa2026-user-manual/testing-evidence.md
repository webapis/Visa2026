# User manual — testing evidence (separate from manual)

**Two surfaces — do not merge.**

| Surface | Audience | Content |
|---------|----------|---------|
| **Officer manual** (`user-manual/`) | Visa officers | Guide prose + screenshots — **green tick only** when tests passed |
| **Testing results report** (separate) | Supervisors, QA, developers | Full pass/fail, run id, commit, per-guide matrix |

**Skill:** [SKILL.md](./SKILL.md) · **Pipeline:** [`USER_MANUAL_PIPELINE.md`](../../../docs/USER_MANUAL_PIPELINE.md) · **Officer content:** [content-policy.md](./content-policy.md)

---

## 1. Green tick on the manual (only indicator)

Officers see **one visual cue** on each guide (and optional reference page): a **green tick** meaning *this guide was verified by automated testing on the published build*.

| Show on manual | Do **not** show on manual |
|----------------|---------------------------|
| Green tick (✓) or Material icon `material/check-circle` in green | Test class names, filters, stack traces |
| Optional short label: **Verified** (translated per locale) | `dotnet test` output, `.trx` links |
| Tooltip optional: date only — e.g. *Verified 2026-09-12* | CI job URLs (unless internal admin page) |

**No red X on the published site** — failed guides must not publish (`fail closed`). Draft/staging may omit the tick.

### Frontmatter (set by pipeline — not hand-edited)

```yaml
verified: true                    # only true after UserManual E2E green
verifiedAt: "2026-09-12T14:30:00Z"
verifiedCommit: "abc1234"         # short sha
screenshotsVersion: "2026.09"     # ties to asset folder
```

**Rule:** `status: published` + `verified: true` required together on CI publish. Agent must not set `verified` manually.

### MkDocs rendering (Phase 3+)

- Jinja / macro reads `verified` from page meta
- Renders green tick beside `title` in guide header
- All locales (`en`, `tr`, `tk`, `ru`) share the **same** verification run for a given `slug` + commit (one E2E journey; translations verified structurally + link validator)

## 2. Testing results report (separate artifact)

Full results live **outside** officer guide bodies.

### Location

```text
manual-test-reports/              # separate from user-manual/ prose
  manifest.yaml                   # tracked — suite registry
  README.md                       # tracked
  latest/                         # generated (gitignored)
    summary.json                  # machine-readable
    summary.html                  # human-readable dashboard
    guides-matrix.md              # optional markdown for supervisors
  runs/                           # archived TRX per run (gitignored)
```

**Implemented (foundation):** `scripts/ci/Write-ManualTestReport.ps1` + `scripts/local/Serve-ManualTestReports.ps1`. See [docs/MANUAL_TEST_REPORTS.md](../../../docs/MANUAL_TEST_REPORTS.md).

**Publish options (pick in Phase 3):**

| Option | URL | Best for |
|--------|-----|----------|
| **A — CI artifact only** | GitHub Actions download | Developers |
| **B — Internal static site** | `manual-test-reports/latest/summary.html` on gh-pages subpath | Supervisors |
| **C — Same host, different path** | `/manual/` vs `/manual-test-reports/` | On-prem IIS |

**Not** mixed into `user-manual/docs/` guide Markdown.

### `summary.json` (generated by `Build-UserManual.ps1`)

```json
{
  "generatedAt": "2026-09-12T14:35:00Z",
  "commit": "abc1234",
  "workflowRunId": "12345678",
  "overall": "passed",
  "unitTests": { "filter": "Category=UserManualDocs", "passed": 12, "failed": 0 },
  "e2e": { "filter": "Category=UserManual", "passed": 5, "failed": 0 },
  "guides": [
    {
      "slug": "person/register",
      "locale": "en",
      "e2eScenarioId": "person-employee-create",
      "status": "passed",
      "durationMs": 94000,
      "screenshots": ["person-register-step-02-employees-list.png"]
    }
  ]
}
```

Pipeline step: after E2E → write `manual-test-reports/` → update guide frontmatter `verified*` from this file → `mkdocs build`.

## 3. Pipeline integration

```text
Build-UserManual.ps1
  ├─ UserManualDocs tests
  ├─ UserManual E2E
  ├─ Write manual-test-reports/latest/summary.json + .html
  ├─ Patch guide frontmatter verified: true (published slugs only)
  └─ mkdocs build   ← site shows green ticks only
```

| Step fails | Manual publish | Green ticks |
|------------|----------------|-------------|
| Unit or E2E red | **Blocked** | Not updated |
| Green | Allowed | Set for passing slugs |

## 4. Localization

| Item | Localized? |
|------|------------|
| Green tick icon | Universal |
| Label **Verified** | Yes — en / tr / tk / ru |
| Tooltip date | Locale date format optional |
| `summary.html` report | **English first** for supervisors; optional tr/tk/ru later |

Same `verified: true` for all locale files of one `slug` on the same build.

---

## 5. Agent rules

| Do | Don't |
|----|-------|
| Run pipeline; let CI set `verified` | Hand-set `verified: true` in drafts |
| Link supervisors to test report URL in **tracking.md** / release notes | Paste TRX or test output into guide body |
| Remove tick if guide set back to `draft` | Show failed test detail on officer pages |

---

## 6. CI validation

| Check | Severity |
|-------|----------|
| `published` + `verified: true` without green E2E in same run | **Fail** |
| `verified: true` hand-edited (no matching `summary.json` commit) | **Fail** |
| Test output block in `user-manual/docs/` | **Fail** ([content-policy.md](./content-policy.md)) |
